# Code-adjacent prose

## Comments

State only what the code cannot show: a constraint, non-obvious reason or warning. Do not narrate the next line or address a reviewer. Match the surrounding code's comment density and idiom.

## Docstrings and descriptions

Start with one active-voice sentence saying what the thing does. Add parameters, return values and errors only when the signature does not make them clear.

## Commits and pull requests

Lead with the outcome. Include motivation, evidence and risk only when they help someone understand or review the change. Avoid template filler and claims the diff or verification does not support.

Before finishing, check that every comment and docstring earns its place rather than narrating the obvious.
